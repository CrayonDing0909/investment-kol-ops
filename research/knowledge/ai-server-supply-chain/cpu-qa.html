CPU 在 AI server 裡還有什麼用？

這頁是 CPU Q&A 的 HTML 閱讀版。目標不是背名詞，而是建立一個能跟大眾解釋的 mental model： GPU/ASIC 是做算力，CPU 是讓 agentic AI workflow 長時間穩定運作的調度層。

Last updated: 2026-05-10 · status: draft · source-backed + BusinessNext reference

問題

CPU 在 AI server 裡還有什麼用？AI 工作負載不是都靠 GPU / ASIC 嗎？為什麼 AMD、Intel、Arm、甚至 NVIDIA 都開始講 CPU？

短答案

GPU / ASIC 負責大規模矩陣運算，但 CPU 負責「協調整台機器」：跑作業系統、處理資料搬運、I/O、前後處理、排程、呼叫工具、查資料庫、執行程式、把任務餵給 accelerators。 當 AI 從「問一句答一句」變成 agentic workflow，CPU 要處理的 orchestration 變多，甚至可能成為延遲瓶頸。

簡單說：GPU/ASIC 是算得快，CPU 是讓整套系統跑得動。

心智模型

從聊天機器人到 AI 代理

以前的 chatbot 像「櫃檯問答」：使用者問一句，系統把任務丟給 GPU 推理，回一個答案。 Agentic AI 像「專案經理 + 一群員工」：它會拆任務、分派子任務、查資料、呼叫工具、寫程式、重試、自我修正。

這些任務安排、資源調度、系統互動，很多都不是 GPU 擅長的事，而是 CPU / system layer 的工作。

廚房比喻

GPU / ASIC 是一排很猛的廚師，專門快速做菜；CPU 是廚房領班，負責接單、分工、送食材、決定先做哪道、處理臨時狀況。 菜色越複雜、訂單越多、同時開越多工作流，領班越重要。

稍微技術一點

  • GPU / ASIC：處理 tensor compute、training、inference 的高密度計算。
  • CPU：處理 host code、資料前後處理、I/O interrupt、network stack、storage access、RPC、container orchestration、scheduler、logging、tool execution、model server control loop。
  • Agentic AI：不是一次推理，而是多個 steps、tools、agents、memory / database / code execution 的長流程。
  • Latency bottleneck：BusinessNext 引述 Georgia Tech + Intel research，CPU 在 agentic workload 中可能占總延遲過半。這 claim 需要原始 paper 驗證，但方向合理。
