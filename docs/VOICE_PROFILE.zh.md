# 語氣設定

## 目的

這份文件定義投資內部文章的預設語氣。

目標不是寫出「很順的 AI 文章」，而是讓文章像一個正在建立投資判斷的
工程背景投資人：說清楚自己讀到了什麼、哪裡還不確定、以及市場地圖如何
被更新。

## 核心語氣

- 可以用第一人稱，但不要變成自我中心。涉及判斷時，用「我目前會這樣看」、
  「我會先把它理解成」、「我還需要驗證」這類語氣。
- 研究優先：不要只給結論，要讓讀者看見學習路徑。
- 先保留原始想法，再整理成文章。第一版應該像研究口語稿，不要一開始就
  變成完整教學文。
- 還沒驗證的想法要明確寫成「假設地圖」，不能包裝成定論。
- 用自然中文，必要時保留市場或技術上常見的英文詞。
- 用具體 caveat 取代籠統 disclaimer。
- 姿態要謙虛：這是研究與判斷建立，不是喊單。

## 原始語氣優先

- 先寫低整理度版本：
  「最近整理 AI server 相關族群的整體敘事架構，感覺大概有幾條支線。」
- 保留不確定語氣：
  「我想像中」、「感覺」、「大概」、「應該比較像」、「還沒有驗證」。
- 不要急著幫使用者變成漂亮結論：
  原句如果是「CPU 應該是 agent AI 需求帶出來的」，不要改成
  「CPU 是 agentic AI 時代的 system orchestration bottleneck」。
- 可以修順序、補斷句、降低重複，但不要把語氣磨到像媒體稿或投研報告。

## 好的寫法

- 從自己的觀察開始：
  「最近整理 AI server 相關族群，感覺不能全部塞進一句 GPU 外溢。」
- 把支線拆開，但標成假設：
  「CPU 這條我目前比較能理解；HBM、散熱、被動元件又不太像同一個故事。」
- 把證據和觀點分開：
  「AMD 是目前最乾淨的 source-backed 主線；Intel 比較像修復線；
  MediaTek 在官方來源更清楚以前，還是 optionality。」
- 說清楚什麼會改變看法：
  「如果下一次法說沒有延續 server CPU demand，這條 thesis 就要降級。」

## 避免

- 沒有 source 的大句子：
  「市場已經開始...」
- 很 AI 的轉場：
  「這很重要，因為...」
- 過度投研化的詞：
  「核心 thesis」、「底層原因」、「重新定價」、「讀者 takeaway」。
- 喊單語氣：
  「這就是買點」、「下一個贏家」、「必須持有」。
- 太對稱、太模板化的文章結構。
- 硬套比喻。只有在比喻真的能降低理解成本時才使用。

## 文章節奏

1. 從「我最近在整理 / 觀察到什麼」開始。
2. 先承認這還沒驗證，只是目前的假設地圖。
3. 把幾條支線拆開：每條線寫「我目前怎麼想」和「還缺什麼驗證」。
4. 再放 source-backed 的資料，說哪些支線比較站得住。
5. 結尾回到觀察清單，不給交易指令。

## 公開前規則

公開前，每個強 claim 都要被標成以下其中一類：

- `source-backed`：有 primary source 或可靠官方材料支撐。
- `secondary`：有參考價值，但公開前還需要確認。
- `my-interpretation`：清楚標成個人判斷，不寫成事實。
